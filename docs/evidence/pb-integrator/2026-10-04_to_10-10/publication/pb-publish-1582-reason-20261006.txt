No queue record, claim, lease, token, reservation or broker format change versus the live generation f69f70cee227. One change on that base, carried with identical changed lines from the merged PrismaBuild PR 1582 (main a8dec2bf, approved at head f3b2a053 by independent review, merged 2026-10-06): the host CPU controller now credits a PrismaBuild control-plane process that was born inside the sampling interval as non-foreign load, instead of counting it as foreign CPU, which had let the loops the supervisor restarts make the box look busier than it was and defer admissions (Closes #1581). The interval boundary is the boot clock persisted with the previous host sample (boot_ticks, from /proc/uptime, rounded up with Decimal so it can only be late, never early); no wall-clock arithmetic is used. The only new stored datum is one optional integer key, boot_ticks, in the box-local host sample state; it is not a queue record. A sample written before this change has no such key, and so does a sample where the boot clock could not be read (boot_ticks is null then); in both cases the new reader gives no newborn-thread credit for that interval and behaves as the previous generation did. An older reader ignores the extra key. Alternating generations can therefore only under-credit control work, never credit foreign load, so a rolling activation is safe: running actions are untouched and idle loops upgrade independently.
