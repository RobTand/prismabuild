One change on that base, carried with identical changed lines from the merged PrismaBuild PR 1587 (main f100b812, approved at head b7430e64 by independent review, merged 2026-10-06): pbrun --supersedes no longer files its immutable supersession record before the window's preparation. It checks every refusal first with nothing written (the new action_edges.check_supersession, which file_supersession now uses too) and files the record immediately before the consumer row publishes, so a refusal while preparing a staged submission (the stage tier, the phase table, the seal) can no longer leave an old key superseded by a replacement that never published (Closes #1585). Files: tools/fleet/pbrun.py and src/prismabuild/action_edges.py (and the new test file). pbrun is a client script: a rolling activation changes nothing for running actions; a submitter picks up the new behaviour the next time it starts pbrun from the live generation. One case still leaves the record before the row: if the queue's publish call itself refuses after the record is filed, the same submission retried (same work, same key) finds its own record and publishes under the key it names; a refusal before that point leaves no record. A record already stranded by the old order is not repaired (it is immutable). Not changed: the deferred --after path and the release path.
