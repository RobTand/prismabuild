## Scope of Phase 1 (design note section 5; NO shim injection, NO placement preference yet)
Resident-set records and lifecycle, without touching the Docker shim or `_matching_offers`. Deliver in slices, each test-first, each a separate commit, message me after each slice:
1. **Records and CLI.** Set record (immutable body + append-only lease log), per-host copy record, `local_tier_policy.json` (published with the runtime like `ram_tier_policy.json`), and `pbresident publish|status|release` (validate: manifest shape, real sha256 on every entry, whole-directory coverage by listing `canonical_root`, hard maximum lease required). Pure records and validation first.
2. **Capacity.** New ledger kind `local_gib` on tier id `local:<host>`, minted dynamically: `min(policy maximum, f_bavail - D1 floor - docker allowance + bytes the tier already holds)`. D1 (fleet-diskcheck): at least 5% free, and a write of N GiB needs 1.5N+20 GiB free. Decide with evidence who mints it on a Spark (a role like `storage`/`tiers` under the supervisor, or reuse of an existing loop); the design says a per-host `localtier` role, check whether an existing loop can carry it and say why or why not.
3. **Mover.** A movement action pinned to the Spark that copies from the nearest source (dl380g10 stage tier if resident, holding a reader_lease pin on the stage bytes for the copy; else the canonical path), hashes while writing, **fsyncs**, verifies every file's sha256 against the manifest (byte integrity), renames into place, files the copy record. Resumable `.partial` trees; nothing is ever served from `.partial`.
4. **Lease pass and eviction.** Lease = until-date or campaign, **hard maximum required, no forever lease; renewal by live rows stops at the hard maximum**. Eviction follows the note's order exactly: take the per-host `flock(2)` file lock, check pins, write record state `evicting`, rename to `.evicting`, release the lock, delete, **then release ledger tokens**; a restarting pass finishes `.evicting` trees before minting. Pin protection: a pinned copy is never evicted (the pin is the only protection). Cross-host: use the #801 egress-action pattern.
5. **Adoption** of an existing verified directory (sha256 of every file against the manifest, `mv` into the tier root on the same filesystem, record `resident`), as a CLI step, with tests on a temp filesystem. Do not touch `/home/rob/models-local` or any live Spark path.
6. **`pbstatus` view** of sets, copy states, leases and capacity, and the `served_from` field in the attempt record schema (written only as `canonical` in Phase 1, since injection is Phase 2).
