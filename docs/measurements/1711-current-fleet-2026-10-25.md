## Deterministic settlement regression

[The new regression](../../tests/test_checkout_recovery_fixture_settlement_1711.py)
injects a publisher whose copy completes only when its child handle is waited.
It exercises the real recovery fixture, real diagnostic copy and full protected
snapshot. It uses no sleep or scheduling threshold.

- Historical source action `964184b10506330219c4a107c5a4df9c562663de397b07bd0f25286861123b13`
  fails with `fixture returned before its diagnostic copies finished`.
- Current source action `a003e25daba5f74fd3a513d9c5743f7799b9ee9eefe191ae04973468c2000e89`
  passes the regression and four reporting tests, 5 passed, no skips.

For the four-worker replay, reserve four CPUs and 8 GiB. Serial replay and the
regression use one CPU and 2 GiB. All have zero GPU demand and native thread
bounds of one. The repeat arms seal a `repeat=180` stall allowance and an
explicit 900-second payload deadline. For either recovered or current checkout:

```sh
python3 /mnt/shared/prismabuild-fleet/repo/tools/pbrun.py \
  --cwd CHECKOUT --tag x86 --cpus 4 --demand mem_gb=8 \
  --progress-phase repeat=180 --timeout-s 900 --detach \
  --env OMP_NUM_THREADS=1 --env MKL_NUM_THREADS=1 \
  --env OPENBLAS_NUM_THREADS=1 --env PYTHONPATH=src -- \
  /home/rob/venvs/pb-cpu/bin/python3.14 \
  tools/maintenance/checkout_recovery_repeat_1711.py \
  --repeats 20 --workers 4 --label SOURCE_LABEL
```

All full stdout files were read and checked against terminal sizes and hashes.

serial arm and regression receipts pass `pb_verify_claim(hash_payload=true)`;
