### Probe budget beside the observed operation mix

The measured deployed plugin samples about once per second. Each successful
sample requests **five stat calls, five read-only open/close pairs, five listdir
calls, and five claim cycles**. Each old claim cycle creates, writes six bytes,
closes, renames and unlinks. Setup creates the directory and anchor once.
Thus one steady-state sample requests five RENAME, five REMOVE and five small
WRITE operations, plus the read-side loops. These are syscall budgets. Attribute,
dentry, data and open-state caches, NFS compounds and recovery prevent a fixed
one-syscall-to-one-RPC conversion.

The same retained `readonly-<host>-initial.json` windows used in the table above
give this selected-mount operation mix. Rates use their actual monotonic intervals,
30.0462 seconds on sparky and 30.0480 seconds on sparklina.

| Operation | Probe requests per sample | sparky ops/s | sparklina ops/s |
| --- | --- | ---: | ---: |
| stat | 5; GETATTR depends on revalidation | 30.586 GETATTR | 99.541 GETATTR |
| read-only open/close | 5 pairs; claim adds 5 writable pairs | 4.992 OPEN + 24.895 OPEN_NOATTR; 29.921 CLOSE | 5.025 OPEN + 27.290 OPEN_NOATTR; 32.315 CLOSE |
| listdir | 5; READDIR can be cached | 3.129 READDIR | 4.160 READDIR |
| claim create | 5 | 11.682 CREATE | 6.723 CREATE |
| claim write | 5 small writes | 4.992 WRITE | 4.992 WRITE |
| claim rename | 5 | 4.992 RENAME | 4.992 RENAME |
| claim unlink | 5 | 4.992 REMOVE | 4.992 REMOVE |
| other lookup/read traffic | cache and compound dependent | 7.255 LOOKUP; 0.033 READ | 5.924 LOOKUP; 1.564 READ |

The deployed probe is an identified active producer on this filesystem, and the
RENAME/REMOVE/WRITE cadence agrees with its five cycles per second. This does
not attribute every counted RPC to that process. The probe budget does not
explain the original reported 1,779 ops/s, the extra OPEN_NOATTR/CLOSE traffic,
or sparklina's GETATTR excess. The historical 1,779 sample still lacks a
reconstructable capture. The later retained client census also records a
separate, busier sparklina window with 1,254.371 GETATTR/s, so one quiet sample
cannot establish that the remaining producer disappeared. Pathname-aware
per-process capture is still needed for that remainder. No polling removal or
percentage reduction is claimed from these client-wide samples.

## Discriminating lifecycle arms and source repair

The follow-up implements the requested one-step arms in
[`nfs_probe_lifecycle.py`](../../tools/maintenance/nfs_probe_lifecycle.py).
Each action reserves one CPU, 1 GiB, no GPU and one native thread per library.
Each uses a fresh private directory, 1,000 cycles, and before/after
`mountstats` CLOSE errors. Exact-prefix nfsd snapshots bracket each action;
every before count is zero. Active cycles run through published `pbrun`;
privileged server observation only reads procfs through the existing read-only
inspection path. No tracing setting, service or mount changes.

| Arm on sparky | States retained after exit | CLOSE errors added | PB action |
| --- | ---: | ---: | --- |
| Current create/write/close/rename/unlink | 4 | 4 | `61981106d7ab43534e071a84494199591d5c5c4f88d04437fd56bb588028ebf1` |
| Unique name each cycle | 8 | 8 | `97f9511c1397f51446148a4bfc360afe0c120d9756fd1f42f61b2dc1dac9cf39` |
| No rename | 12 | 12 | `435376f12c28aba8fcd28300f5361ea3ce49d8da0d4bb0d1ff041f8575a1e846` |
| Overwrite fixed file; no rename/unlink | 0 | 95 | `2ac9bce3dfe827ff7bdc0feb21b6920f9ddd28165569cf039bd6bc18208135a1` |
| Rename over existing done; no explicit unlink | 4 | 4 | `70b8ac2cd97343e7335c1c34e2371295b69ed8a71a18ecee7a92270237c9c0ca` |
| Create empty, close, rename, unlink | 0 | 0 | `23d109d9f7f358b261dbd6ffc6322bb9b1b4e1ed2b2988bece6860ffede9c9a6` |
| Current lifecycle again after empty arm | 13 | 13 | `f2253d3ec13b7103b54e88a2151bba7d2fd5cadd6366691de94a9e895d477de3` |

Unique names and removing rename do not prevent retention. The overwrite arm
has zero retained states but drops required RENAME coverage and retains one
scratch file. Its 95 CLOSE errors also show that CLOSE errors alone do not
count retained states. The selected empty-file lifecycle preserves create,
close, RENAME and unlink, while eliminating dirty data. The following old
lifecycle still retains states, so the zero result is not a fleet-wide recovery
that happened before the new arm. The exact Linux/NFS stateid failure remains
untraced; this evidence establishes a PB trigger and a bounded mitigation.

`timed_probe` now creates empty scratch instead of writing six bytes. The
write-and-close expression was simplified first, with 48 existing tests passing.
The new deterministic regression then failed because the renamed file contained
six bytes in PB action
`1573328ea1fb11ff0831777c5b6a67331730e1c2f18bea0a88440a0e71f657a1`.
It records actual open/close/rename/unlink order, checks zero file size at
rename, and verifies only the anchor remains. It uses no sleep, wall-time
threshold or load-sensitive assertion.
