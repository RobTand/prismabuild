These are client-wide NFS operation rates for each selected mount, not

the original 1,779 operations/s report. The error counters do not name NFS
error codes and do not attribute an error to a particular stateid.
The separate shared-mount process attribution objective remains incomplete.

## Repair handoff and acceptance

No application handle remains open in the successful reproduction. This pass
therefore adds no speculative PB close, waiter, bell, or timeout change.
Changing the probe to passive by default would remove diagnostic coverage
without repairing already-retained states and is not proposed as a fix.

The next repair belongs at the Linux/NFS boundary. An operator needs a bounded,
identity-correlated client/server CLOSE/error capture for the same private
reproducer and a separately authorized remediation window. A remount-reset
experiment, kernel change, service restart, debug-setting change, and cleanup
of production probe remnants were not performed. Rob owns authority for any
such intervention beyond this task's explicit no-live-change limit.

Acceptance requires the same private reproducer to stop creating retained
state, a current production growth window, and completion of shared-mount
traffic attribution. A passing synthetic diagnostic test cannot establish any
of those facts. Merging this report does not close #1917.

The PRI-46 evidence bundle contains the bounded collector, both reproducer
scripts and submission drivers, raw server/client snapshots, full PB readbacks,
claim checks, and a manifest of file hashes. The published runtime changed
externally during collection from `e9e9d9077212-1792715962-50f991688c86` to
`9dce28460e76-1792959923-b5904f02524e`. This investigation neither published a
runtime nor restarted a service; it claims no controlled deployment comparison.
